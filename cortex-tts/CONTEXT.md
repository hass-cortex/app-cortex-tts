# Cortex TTS — Domain Language

On-device text-to-speech over ONNX models that have no text front-end of their
own. The vocabulary below covers what callers reach for across the codebase;
general programming patterns are not listed. Almost every noun here has a
second, unrelated meaning somewhere else in the same request path, which is
what this file exists to prevent.

## Language

### The text path

**Text path**:
Everything `prepare()` does between the caller's string and the model's input:
normalise, convert, split. It is the product, not a preprocessing detail — the
models read glyphs, so whatever this produces is what gets spoken.
_Avoid_: "preprocessing", "cleanup" (both suggest something optional)

**Normalisation**:
Expanding the fixed shapes a sensor produces — units, percentages, clock
literals, ISO dates — into words, in the **Locale**'s language. A bare `80` is
read as "eighty" only when `expand_numbers` asks or the model cannot say a
digit (`needs_number_words`, Hojo).
_Avoid_: "conversion" (the other pass), "normalize the audio" (see Flagged
ambiguities)

**Script conversion**:
The Traditional-to-Simplified glyph swap (OpenCC `t2s`). Glyph shape only —
`tw2sp` would also rewrite vocabulary (設定 to 设置) and change the words said.
_Avoid_: "translation", "normalisation", "correction" (the Traditional text
was not wrong; the model cannot pronounce it)

**Pass**:
One substitution in the ordered table in `text/passes.py`: a pattern, a
rendering, and the option that switches it off. Order is the contract — a
construct claims its number before the bare-number pass reads it as a
quantity.

**Prepared text**:
What the model is actually asked to say, after every pass; the admin UI shows
it under that name.
_Avoid_: "output" (the output is audio), "result"

**Segment**:
One synthesis-sized piece of Prepared text: at most what
`ModelSpec.segment_limit` allows on the chosen model, always ending in
sentence-final punctuation. Several sentences may share one; one long sentence
may span several.
_Avoid_: "sentence" (a **Sentence** is what the splitter sees on the way in; a
segment is what the engine gets on the way out), "chunk" (see below — a
segment is what the engine is handed, a chunk is what it hands the model)

**Chunk**:
What one call into the model actually carries. Usually the whole Segment; on
a model declaring `ModelSpec.max_text_tokens` the engine cuts an over-budget
segment into several, using the model's own tokenizer and its own splitter.
The cut is the engine's because only the engine can count the model's tokens.
_Avoid_: "segment" (the pipeline decides those, in characters, before any
model is chosen); and do not read this into **Chunk streaming**, which is
about audio — one chunk of text yields many pieces of streamed audio

**Locale**:
What the pipeline knows about one language: how its numbers are read, which
stop ends a sentence, the rewrites only it has (`text/locales.py`). Chinese
and English are written; every other language gets the generic one —
`num2words`, CLDR unit names and dates via `babel`, nothing it is not sure of.
Adding a language is adding a locale, never a branch. A model declaring
`reads_numerals` makes the generic locale stand aside; a written one is kept.

**Sniffed language**:
The tag settled on when neither the request nor the voice declares one — kana
is `ja`, 漢字 outnumbering Latin _words_ is `zh` (`zh-Hant` in Traditional
glyphs), anything else `en`. A fallback, not the rule.
_Avoid_: "dominant script", "detected language"

**Identifier reading** / **Quantity reading**:
Two ways to say the same digits: a number welded after a letter is a label
read digit by digit (`P0` → "P zero"); one before a letter carries a unit and
stays a quantity (`24V` → "twenty-four volts").

**Request flag**:
`normalize_text` / `expand_numbers` / `convert_script` / `taiwan_readings` on
the wire. The last two are Chinese's, and absent means the language decides.
The first and third are a capability for a caller whose text is already
prepared, not a preference; `expand_numbers` is off unless asked, except on a
model that cannot say a digit; `taiwan_readings` is a preference.

**Text rule**:
A stored default for the request flags, per model and language (`text_rules`
in the settings), answering a switch the request left out before the
pipeline's own answer. Rules cascade per switch, the most specific winning.

**Taiwan reading** / **Stand-in**:
A word Taiwan reads differently from the mainland (垃圾 lè sè), and the
homophone it is respelled with so the model says it that way (乐色). The table
is generated by `scripts/taiwan_readings.py`, never edited by hand.
_Avoid_: "pinyin hint" (measured fragile; not what the app does)

### Models and voices

**Catalog model**:
An entry in `catalog.py` — id, file list, Hugging Face repo, capabilities,
cost figures. The set of _downloadable_ models; weights arrive on first
download and live under `/data`.
_Avoid_: "built-in model" (nothing is built in)

**Engine**:
A loaded model behind the `Engine` protocol (`PresetEngine` for the 40M,
`MossEngine`, `OmniVoiceEngine`; `MossEngine` also satisfies
`StreamingEngine`). One synthesis at a time, because a session carries state
across a render.
_Avoid_: "model" for the loaded thing — a _model_ is files on disk, an _engine_
is the runtime holding memory

**Resident**:
Loaded into memory. The registry keeps at most `max_loaded_models` engines and
evicts the least recently used; what two cost together is in `docs/models.md`.
_Avoid_: "cached" (eviction is about memory, not staleness)

**Voice**:
A selectable speaker, always belonging to exactly one model: a built-in slot
(`hojo_zh_f_01`), a **Reference recording**, or a **Designed voice**, as the
model's capabilities allow. On a model without `language_choice` the voice is
the only place a language is declared, so picking the voice picks the
language.
_Avoid_: "speaker" (the embedding slot inside the model)

**Designed voice**:
OmniVoice's third kind: not a slot in the bundle and not a recording, but a
short instruction built from the model's **closed** attribute vocabulary. The
nine on offer are chosen in `engine/omni.py`; an attribute outside the
vocabulary is refused. Reported as `source: designed` beside `builtin` and
`reference`, because the three cost different amounts to render.
_Avoid_: "prompt", "style" (a fixed list, not free text), "preset" (the 40M's
word)

**Reference recording**:
An audio file _and_ the words spoken in it — both, always. The recording
supplies the timbre; the transcript tells the model which sounds map to which
text. A wrong transcript degrades the clone with no error, so it is validated
on the way in.
_Avoid_: "sample" (suggests something disposable), "voice file"

**Conditioning** / **Sidecar**:
What an engine derives from a Reference recording before it can clone it —
codec frames, a prompt. The dominant cost of a cloned
utterance, so it is cached by reference id and written beside the recording
per engine as `<id>.<fingerprint>.<engine>.*`, the _sidecar_; the fingerprint
is the invalidation. Disposable.
_Avoid_: "cache file" (says nothing about what is in it or when it is stale)

**Raw transcript** / **Transcript**:
Two fields: the _raw transcript_ is what a person typed; the _transcript_ is
what the model is told, after the Text path has run over it.

**Cloned voice**:
The voice a Reference recording defines. It exists the moment the reference is
stored — no training, no build step — and Home Assistant sees it within
seconds via the models-changed event.

### Latency

**Live reply**:
A reply spoken over `/api/speak/live` while the writer is still producing it:
text frames in, audio frames out, one WebSocket per reply. The _app_ decides
what to render when and when to release it (`cortex_speech/pacing`); the
integration forwards the words and plays the sound.
_Avoid_: "streaming" unqualified (see Flagged ambiguities)

**Real-time factor (RTF)**:
Render seconds over audio seconds of one request, fixed cost included. Of a
_voice on this host_: the median of its last eight requests under the
execution provider now in use, `null` until three exist; per model and voice,
never pooled, borrowed, or carried from another machine. Loading a model is
in no request.
_Avoid_: "cost line", "slope", "fixed_s" (there is no fit)

**Verdict**:
What a voice's RTF says a live reply will be: **streaming** under this host's
threshold (`stream_rtf` in settings, `STREAM_RTF` 0.8 by default), **buffered**
otherwise or while unmeasured. Made once per reply, at
`ready`, never revised. `auto` takes it; `streaming` and `buffered` overrule
it. Argued in `docs/adr/0001-rtf-threshold-pacing.md`.

**Streaming** (outcome):
One sentence per request, rendered as the words arrive; nothing plays until
`BANK_S` (6 s) of audio has been rendered or the reply has been rendered
whole, then each sentence goes out as it finishes. The bank is the only hold
and a constant: replayed over 182 multi-sentence production replies it leaves
at most 2% a gap under two seconds on a 0.6–0.7 host and none on a GPU host,
where releasing each sentence unheld broke a third.
_Avoid_: "unheld", "planned" (neither is an outcome)

**Buffered** (outcome):
Rendered as the words arrive — every complete sentence waiting as one request
whenever the engine is free — and released only once everything has been
rendered. Never runs dry. About releasing, not cutting: a reply that fit one
request is still _buffered_.
_Avoid_: "whole" (not an outcome; a one-request reply is `done.batches == 1`)

**Lead**:
Audio handed to the listener minus wall time since the first byte left. The
least value over a reply is `min_lead_s` in the `done` frame and the
integration's playback-margin sensor; negative means it ran dry by that much.
_Avoid_: "buffer" (the listener's buffer is downstream and invisible)

**Abandoned**:
A render whose listener left. Every engine takes a `stop` check between the
units it produces — a decode step, a diffusion step, a codec chunk — so the
lock is released within one unit and nothing is recorded against the model.
Not a failure: `AbandonedError` is the caller's own news coming back.

**Chunk streaming**:
An engine emitting audio before a whole segment is finished — a `ModelSpec`
capability and the `StreamingEngine` protocol, true for MOSS-TTS-Nano only. A
Live reply uses it inside each request; the live reply
itself is per _request_ and needs no engine support.

**Time to first audio**:
The wait a listener experiences: request in, first frame out. The only number
that changes when streaming is turned on.
_Avoid_: "latency" (unqualified), "inference time"

**Inference time**:
What the model cost, summed across segments. Not a wait: segment one is
playing while segment three is generated.

### Configuration

**Option**:
A field in the app's configuration tab, stored by the Supervisor and declared
in `config.yaml` — only the log level and the discovery key, because both must
be settled before the process starts. Changing one costs a restart; changing
its schema costs a rebuild.
_Avoid_: calling a Setting an option (it promises a restart that does not
happen)

**Setting**:
A field the app stores itself, in `settings.json` beside the models, changed
in the admin UI and over `PUT /api/settings`. Read afresh on the next request,
except the two ONNX Runtime binds when it creates a session (threads,
execution provider), adopted by dropping whatever is resident; the thread
count's BLAS/OpenMP side is fixed at import and waits for a restart.

## Relationships

- A **Catalog model** becomes an **Engine** when the registry loads it, and is
  **Resident** until evicted; downloading, loading and evicting are three
  separate transitions the UI shows.
- A **Voice** belongs to exactly one model. `ModelSpec` carries nine
  independent capability booleans — `builtin_voices`, `cloning`,
  `designed_voices`, `chunk_streaming`, `temperature`, `language_choice`,
  `style_instruction`, `reads_numerals`, `needs_number_words` — and a voice
  list is the sources concatenated, never one chosen over another.
- `max_audio_s` is a figure rather than a flag: the most audio one call can
  produce before the rest goes unspoken. Only a model that establishes a
  ceiling declares one (`max_chars_per_segment` has no default either), and
  `ModelSpec.segment_limit` turns whichever bounds exist into a length of text
  for the script at hand; `docs/models.md` is where each is measured.
- The **Text path** runs before any engine is touched, so `/api/preview`
  answers without loading a model.
- **Normalisation** runs before **Script conversion**: it emits Traditional
  number words that only the conversion pass can make pronounceable.
- A **Live reply** is spoken in requests — one sentence each when streaming,
  every complete sentence waiting when buffered — each prepared through the
  **Text path** into **Segments** on its own; **RTF** is measured per request,
  because a request is what the listener waits for.
- A **Reference recording** and the models-changed event are the two things
  that alter the voice list without a config-entry reload.

## Flagged ambiguities

- **"normalise" is two unrelated operations in one request.**
  `text/zh/normalize.py` rewrites numerals into words; `audio.normalize_level`
  scales a waveform's amplitude. Say "text normalisation" or "level
  normalisation" — never the bare verb.
- **"streaming" is three things.** Home Assistant's _streaming input_ (the
  conversation agent feeding text in as it is written), a **Live reply** (text
  in, audio out over one socket), and **Chunk streaming** (an engine emitting
  audio mid-segment). The _outcome_ named `streaming` is the first of the two
  ways a live reply is released, beside `buffered`. Name which one, every
  time.
- **"chunk" is two things.** A **Chunk** of text is what one call into the
  model carries; a chunk of audio is what **Chunk streaming** emits from
  inside one of those calls. One of the first yields many of the second. Say
  "text chunk" or "audio chunk" where both are in reach.
- **"voice" without a model is meaningless.** `hojo_zh_f_01` exists on the 40M
  and nowhere else, `Yuewen` only on MOSS, and a reference is a voice on
  _every_ model that can clone, under the same id — so even a reference id
  needs a model beside it.
- **"transcript" is two wire fields** — `raw_transcript` and `transcript`; they
  differ exactly when the text path changed something.
- **"temperature"** is the sampling temperature of the language model. Nothing
  here measures heat, but the unit table expands `°C`, and both appear in the
  same file.
- **"default_voice"** is a stored _name_, not a resolved voice. It is ignored
  when the chosen model does not offer it, and both the synthesis path and the
  admin UI fall back to the first available voice.
- **"model" in the admin UI** means a Catalog model; **"model" in a log line
  from the engine** usually means the loaded ONNX session. The distinction is
  Catalog model versus **Engine**.
